Privasi

TA Assess dirancang untuk memproses data seperlunya. Jawaban mentah tidak dikirim ke Google Sheets oleh jalur hasil utama. Browser dapat menyimpan progres sementara untuk pemulihan sesi.

Data minimalJawaban mentah tidak disimpanKamera lokal
  • Kamera hanya digunakan untuk kalibrasi tampilan ketika fitur tersebut aktif.
  • Frame kamera tidak menjadi bagian dari payload hasil.
  • Metadata keamanan dibatasi agar tidak berubah menjadi rekaman jawaban peserta.
  • Mode tamu tidak membuat riwayat akun.
Prinsip utama: data teknis dan data hasil dirancang terpisah dari jawaban mentah.

Metodologi Asesmen

TA Assess adalah platform self assessment. Status instrumen ditampilkan secara terbuka sehingga pengguna dapat membedakan versi demo, pilot, dan instrumen yang benar benar telah memiliki bukti validasi.

DEMOPILOTNot ValidatedVersioned
  • Skor ditafsirkan secara relatif terhadap skala instrumen.
  • Skor bukan persentil populasi karena proyek belum memiliki norma populasi yang sah.
  • Bahasa hasil bersifat probabilistik dan reflektif, bukan kepastian tentang seseorang.
  • MBTI yang dimasukkan pengguna bersifat informasi tambahan dan tidak mengubah skor Big Five.

Algoritma dan Mesin Insight

Mesin hasil menggunakan kombinasi validasi input, normalisasi skor, statistik profil, pemeriksaan kelengkapan, dan aturan Smart Insight. Tidak ada model AI klinis yang membuat diagnosis.

1. ValidasiMemeriksa ID, jumlah dimensi, rentang skor, jumlah jawaban, status laporan, dan kecocokan sesi.
2. NormalisasiMembersihkan nilai, menghitung completion rate, statistik profil, dan skor relatif 0 sampai 100 terhadap skala asesmen.
3. InsightMengurutkan dimensi, mencari pola kedekatan skor, lalu menghasilkan ringkasan dan pertanyaan refleksi berbasis aturan.
4. IntegritasMemakai session proof server, HMAC, report ID unik, serta signature laporan untuk pemeriksaan integritas.
5. RecoveryQuestion Bank memiliki fallback lokal, autosave dapat dipulihkan, dan diagnostik teknis mencatat error tanpa jawaban mentah.
6. AuditBackend mencatat event teknis minimum untuk membantu menemukan kegagalan tanpa menjadikan event log sebagai tempat penyimpanan jawaban.
Catatan: pemeriksaan otomatis dapat mendeteksi kondisi tidak normal dan memulihkan jalur yang aman, tetapi tidak boleh memodifikasi source code produksi secara otomatis.

Keamanan Akun

Sistem akun menggunakan Google Apps Script dan Google Sheets pada tahap pengembangan. Password tidak disimpan sebagai teks biasa, session menggunakan token, dan percobaan login dapat dibatasi.

Password hashingSession TTLLockoutAudit Event

Untuk deployment dengan kebutuhan keamanan tinggi, arsitektur sebaiknya dipindahkan ke identity provider atau database autentikasi khusus dengan mekanisme password hashing modern.

Setup Backend

Google Apps Script menjadi penyimpanan terstruktur untuk hasil, dimensi, verifikasi, event, registry asesmen, analytics, dan konfigurasi. Vercel API berfungsi sebagai gateway sesi dan submission sebelum request diteruskan ke Apps Script.

  • Question Bank dipisahkan dari backend hasil.
  • Secret server disimpan sebagai environment variable atau Script Property, bukan di frontend.
  • Submission hasil memerlukan server proof yang dibuat gateway.
  • Verification menggunakan signature laporan ketika secret verifikasi telah dikonfigurasi.

Pemeriksaan Sistem dan Perbaikan

Pipeline pemeriksaan proyek memvalidasi file penting, referensi halaman, konfigurasi runtime, wiring security, route admin, header kamera, dan struktur dokumentasi.

Strategi recovery: kegagalan Question Bank dapat kembali ke data lokal yang kompatibel, progres asesmen dapat dipulihkan dari session storage, dan error frontend dapat dikirim sebagai metadata teknis.

Perbaikan otomatis difokuskan pada recovery yang aman. Source code tidak diubah sendiri oleh aplikasi saat pengguna menjalankan asesmen.
